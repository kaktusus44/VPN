# Смена IP работающего VPN

На уже подготовленной управляющей Ubuntu можно обновить репозиторий
и запустить ротацию одной командой:

```bash
wget -qO- https://raw.githubusercontent.com/kaktusus44/VPN/main/scripts/bootstrap-ubuntu-control | bash -s -- --rotate
```

Параметр `--rotate` запускает смену IP существующего VPN, без sudo на управляющей
машине, установки пакетов и генерации SSH-ключей. Обычный bootstrap
без этого параметра по-прежнему запускает развёртывание.

Либо обновите уже скачанный репозиторий и запустите напрямую:

```bash
cd ~/VPN
git pull --ff-only
scripts/rotate-endpoint
```

Скрипт последовательно спросит:

1. Роль сервера `main`/`reserve` и доступный сейчас SSH IPv4.
2. Прежний SSH IPv4 (Enter, если он не менялся).
3. Пользователя SSH (по умолчанию сохранённый или `root`). Для пользователя,
   отличного от root, нужен sudo без пароля на VPS.
4. Что меняем: `1` — адрес подключения к VPN, `2` — выходной адрес в интернет,
   `3` — оба адреса.
5. Новые значения только выбранных адресов. Второй адрес сохраняется.

Порт и ключ не спрашиваются: используются сохранённые настройки или порт `22`
и ключ `~/.ssh/vpn_ansible`, созданный при подготовке управляющей машины.
Нестандартные значения можно задать через `VPN_SSH_PORT` и `VPN_SSH_KEY`;
они имеют приоритет над сохранёнными настройками. Если ключ отсутствует,
скрипт выдаёт понятную ошибку и не создаёт новый.

`auto` для выхода возвращает выбор исходящего адреса операционной системе.
При запуске через `wget | bash` ответы читаются с терминала. Без терминала скрипт
выдаёт понятную ошибку; для автоматизации есть `VPN_NONINTERACTIVE=1`,
`VPN_SSH_HOST`, `VPN_SSH_USER`, `VPN_SSH_PORT`, `VPN_SSH_KEY`,
`VPN_ROTATE_WHAT=entry|exit|both`, `VPN_NEW_ENTRY_IPV4`, `VPN_NEW_EXIT_IPV4`.
При автоматизации режим определяется заданными новыми адресами, если явно
не указан. Вопросы о добавлении IP требуют явного `VPN_ADDITIONAL_IPV4`.

Новый SSH IP должен быть доступен заранее. Если выбранный VPN IP ещё не настроен
в ОС, скрипт предложит добавить его как `/32`: подтверждайте только адрес,
уже прикреплённый у хостера. Основной маршрут и старые адреса не удаляются.

Роль `vpn_readdress` обновляет существующие конфигурации Xray, NAT AmneziaWG,
исходящий адрес DNS, клиентские профили и ссылки. При смене SSH IP обновляются
связанные настройки мониторинга и известные узлы из сохранённого inventory.
Если второй узел отсутствует в inventory, укажите его через `VPN_MAIN_IP`
или `VPN_RESERVE_IP` и повторите команду, указав прежний SSH IP.

Ключи и UUID сохраняются. Перезапускаются только сервисы с изменёнными
конфигурациями; смена только входного IP не требует перезапуска VPN.
Резервные копии находятся на VPS в `/var/lib/vpn/ip-change-backups/`.
При ошибке применения роль пытается восстановить прежние файлы и сервисы.

Обновлённые клиентские файлы сохраняются в `exports/<текущий SSH IP>/`.
На VPS обновляются `/var/lib/vpn/client-*.awg.conf`, `amneziawg-client-configs.txt`,
`amnezia-vpn-links.txt`, `client-links.txt`, обе ссылки Xray и, если есть,
`xray-tun-client.json` и `telegram-proxy-links.txt`.
Ссылки получают новый входной IP, ключи и UUID сохраняются.

В консоли сразу выводится блок с путями Amnezia, двумя ссылками Xray и ссылками
включённых Telegram-прокси. Для Xray и Telegram указаны пути на VPS и локально.
При смене входного IP импортируйте
профили заново; при смене выходного IP переподключите клиентов, чтобы старые
соединения не продолжали использовать прежний NAT.
